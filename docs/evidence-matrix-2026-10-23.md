# 证据矩阵按需读取与完整导出

打开联读空间原先会取回全部完整研究回答，记录多时拖慢普通阅读；证据矩阵的旧导出只列引文，缺少原回答、模型和原提问范围。这轮把日常浏览与用户主动导出分开处理，保留已有阅读、问答和图谱判断流程。

## 行为

- 联读空间只预读最多100条问题摘要供输入建议，不再GET旧的全量notebook接口；矩阵进入时才读取。每页20条，按当前最多8篇的原提问成员或引用匹配，在全部历史中检索问题、标题、个人思考、原回答与引句，支持多词和Unicode大小写折叠、字面百分号/下划线。
- 切换选篇或检索回到第一页；迟到的旧请求不替换新组数据。读取错误有明确重试，不伪装成空记录。长个人思考折叠显示；原文不可用仍可查看历史证据，不能误开不可用文件。
- 导出全部匹配的Markdown/JSON，不限于屏幕当前页。保留原问题、完整回答、个人思考、原选篇、模型、记录ID/修订/时间、全文研读/选区的历史元数据、完整引用及组外来源；逐列区分“本次回答未引用”，不能据此断言论文无证据。
- 导出总数、文献元数据、回答及来源版本标识来自一个SQLite只读快照，其他窗口更新不混入半新半旧结果。逐条输出，不在服务器一次装入全部完整回答。每个导出单独连接、串行迭代，在正常完成或取消时关闭；不持有写锁，不生成服务端导出副本。
- 读取时核对当前登记版本及可用状态；历史摘录和原始回答不被改写。版本一致仅指记录版本，不等于AI推论科学验证，也不是再次阅读磁盘全部PDF。本次查看、搜索、导出都不调用AI或建立/确认图谱关系。
- 导出失败可重试和取消，切换组/关闭后不落下旧文件；尾部完成标志缺失时不把截断文件当成功。Markdown转义内容，避免把原文或笔记中的HTML当作页面代码。JSON保留结构和原始值。

参考成熟项目的连续习惯：[Zotero笔记](https://www.zotero.org/support/notes)支持关联文献的笔记与检索；[Open WebUI知识库](https://docs.openwebui.com/features/workspace/knowledge/)明确检索与全文上下文模式并要求对照原文。本轮采用可检索、可携带且保留来源的流程，没有复制其代码或把本站引用展示视为科学验证。
