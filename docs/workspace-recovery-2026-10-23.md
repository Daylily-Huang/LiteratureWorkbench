# 独立工作台恢复与文件重连

目标：备份中的 PDF、批注、研究记录与缓存可以在独立工作台中继续使用。当前默认工作台和原始关联文件保持原位；用户通过“数据与备份”手动创建、打开或关闭恢复工作台。

## 恢复行为

- 完整备份经文件清单、哈希、数据库完整性和外键检查后，再生成独立工作台。仅数据库的备份仍可生成原样恢复副本，但不能冒充完整可读的文献恢复。
- 文献ID、组/关系/笔记ID与正文内容保留；PDF连接到副本的关联文件夹或导入库，重新核对Windows根目录和文件身份，追加新的文献版本。关联库保留原文件夹显示名称，旧版本和旧来源信息保留作历史。
- 批注基线与撤销快照、导入确认路径及解析输出均指向副本；解析输出保持系统要求的相对路径。备份未包含的不可用/历史文件保留记录并明确计数，不能直接阅读。
- 旧队列任务失败且不可自动重试，旧翻译任务过期，未完成导入终止，旧文件移动/清理所有权不复用，一次性外发授权撤销。用户后续仍可正常导入PDF、添加关联文件夹并手动提问。
- 完成恢复不自动启动进程；点击“打开恢复工作台”才启动独立服务。顶部标识当前为恢复副本，打开请求与真正完成启动有明确区别。可单独关闭该副本服务，再次打开复用原副本。
- 恢复服务使用独立Cookie与运行锁/进程身份，原服务会话保持可用。默认桌面图标仍打开默认工作台；高级命令为 `start-recovery <workspace>` / `stop-recovery <workspace>`，只接受已就绪且位置核对通过的恢复工作台。原有 `start` / `stop` 不增加任意数据目录选项。
- Windows长路径支持涵盖文件句柄打开、目录扫描/监听、导入移动及批注读写/恢复；规范路径用于存储与边界比较，扩展路径用于I/O。原有符号链接、重解析点、硬链接、文件身份与所有权检查仍执行。

## 成熟产品参考

[Zotero数据目录说明](https://www.zotero.org/support/zotero_data)区分导出与完整备份，提醒数据库和附件需一起保全；[关联文件缺失说明](https://www.zotero.org/support/kb/missing_linked_file)解释跨机器绝对路径差异。本轮据此补齐“恢复后实际可读”的验证，自动把备份中的文件连接到独立副本，而非仅解压后声明恢复成功。

## 当前边界

这是当前机器上的独立恢复工作台，未把默认工作台原位替换。已就绪副本使用固定绝对路径，不能在资源管理器直接挪动后继续打开；应从备份重新生成。跨机器备份导入、重新配置路径/模型、整机安装与分发许可仍需后续实现和验证。密钥和模型权重不在备份中；同机器现有凭据可用，新机器须配置。受控模型测试证明工作流，不证明科学结论质量或商业就绪。
