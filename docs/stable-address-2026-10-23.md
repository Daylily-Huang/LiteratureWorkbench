# 启动地址稳定与端口占用保护

本轮修复重启后地址反复变化、同一浏览器难以重新找到未同步草稿的问题。本机原默认端口58380实际绑定返回WinError10013，因此旧实现不断退回临时端口；现在每个工作台记住自己成功启动的地址，重启优先复用。不能据此承诺端口永不被占用，或声称浏览器草稿可自动跨地址迁移。

## 行为与依据

- 启动时先绑定127.0.0.1监听套接字，再把同一套接字交给HTTP服务，直到退出才释放，移除“探测可用—关闭—重新绑定”的空档。Windows使用SO_EXCLUSIVEADDRUSE，不启用可抢占其他服务端口的SO_REUSEADDR；套接字不继承给worker。参照[微软套接字说明](https://learn.microsoft.com/en-us/windows/win32/winsock/using-so-reuseaddr-and-so-exclusiveaddruse)、[Python3.12套接字文档](https://docs.python.org/3.12/library/socket.html)及本机固定Uvicorn0.51的预绑定套接字实现（[上游对应代码](https://github.com/Kludex/uvicorn/blob/0.51.0/uvicorn/server.py)）。
- 地址记录只包含格式版本、工作台路径指纹与端口，保存在各自的`runtime/launcher/address.json`，不含会话或控制密钥。API和worker均已就绪后才记住新地址，失败启动释放监听且不覆盖上次记录。正常沿用既有地址时无需重写记录。
- 地址不可用时申请本机备用端口，启动成功后记住新地址；不向占用端口的程序发送健康或控制请求，不终止它。既有启动复用仍要求精确进程身份、健康状态和控制令牌，不借用其他程序的200响应。
- 地址文件限4KiB，拒绝无效/特权端口、其他工作台复制来的记录，以及链接/硬链接等不安全存储。损坏记录会重建并明确提示；仅地址记录不可用时，阅读仍可启动，并标记本次地址无法记住。
- 正常启动不额外打扰阅读。“数据与备份”可查看和复制当前地址；地址变化或记忆失败时才在页面显示简短说明及查看入口，保留上次地址供核对。旧地址的草稿不伪装成已迁移，也不会自动访问旧端口。
- [浏览器localStorage按来源保存](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)，来源包含协议、主机与端口。稳定地址改善正常重启体验，但清除浏览数据、换浏览器或端口冲突仍不保证找回未同步草稿；仍应同步到数据库或导出。
